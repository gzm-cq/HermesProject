# 编写计划

编写全面的实现计划，假设工程师对我们代码库零上下文。记录他们需要知道的一切：每个任务要修改哪些文件、代码、测试、如何验证。将整个计划拆成小步骤任务。DRY。YAGNI。TDD。频繁 commit。

**计划保存位置：** `docs/superpowers/plans/YYYY-MM-DD-<feature-name>.md`

## 流程
1. **分析输入** — 阅读规格说明/需求，识别所有需要修改的文件
2. **架构审查** — 确定模块边界、依赖关系、变更顺序
3. **任务分解** — 每个任务 2-5 分钟，包含：文件路径、代码改动、测试、验证步骤
4. **依赖排序** — 确保任务按正确顺序执行
5. **输出计划** — 保存到 docs 目录并提交

## 约束
- 每个任务独立可测试
- 优先使用现有模式和 API
- 不引入新依赖除非必要
- 任务粒度：单文件修改或小批量相关修改
