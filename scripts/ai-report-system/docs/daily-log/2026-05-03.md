### 1. 管线确定性改造（三处修复）

#### 问题发现
运行"智能制造AI能力建设可行性分析报告"管线时暴露出两个根因问题：
- **optimize_structure 输出6章而非7章**：用户聊天确认的7章目录只写入了 `overall_strategy` 文字描述，未填充 `chapter_prompts` 结构化字段；LLM 从文字描述重生成时丢失了章节数量。
- **synthesize 报警 chapter_prompts 为空**：同上根因，章节未透传到下游节点。

用户指出核心原则：**report_goal.json 是用户在每个决策点上冻结的确定性记录，管线各节点只读、不猜、不改。**

#### 修复 A: `run_report.sh` 移除 `pre_search`
- 背景：`pre_search` 原设计是为 LLM 生成目录提供参考文章
- 决策：目录已在聊天中确认，无需 LLM 重生成，`pre_search` 在标准流程中没有位置
- 改动：移除 L162-L166（pre_search 后台启动）和 L179-L184（等待 pre_search 完成）
- 文件：`scripts/run_report.sh`

#### 修复 B: `optimize_structure` 去掉 LLM 重生成分支
- 背景：该节点原有两条路径——有预定义直接跳过，无预定义则 LLM 重生成
- 决策：去掉 LLM 重生成分支。`chapter_prompts` 为空时直接 `raise ValueError` 报错退出
- 效果：只要用户确认目录写法有遗漏，管线在 optimize_structure 就会快速失败，不会静默凑出错误章节
- 文件：`src/graph/report_graph.py` L560-L579 → 替换为 `raise ValueError`

#### 修复 C: 确认 `key_points` 链路已通
- 验证 `content_generator.py` L175/196/226：`key_points` 从 `chapter_prompts` 读取 → 注入 `context.chapter.key_points` → prompt 要求"必须覆盖所有要点"
- 结论：代码链路正确，无需改代码。问题只是写入 `chapter_prompts` 时 `key_points` 留了空数组
