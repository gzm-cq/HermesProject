# 记忆体系架构设计

## 一、整体架构

整个记忆体系分为 **5 层记忆管理机制**：

| 层级 | 名称 | 数据存储 | 生命周期 | 管理方式 |
|------|------|----------|----------|----------|
| L1 | Session DB | SQLite sessions | 会话级 | 自动，Hermes 内置 |
| L2 | MEMORY.md | `~/.hermes/memories/MEMORY.md` | 跨会话 | Agent 手动写 + 定期清理脚本 |
| L3 | USER.md | `~/.hermes/memories/USER.md` | 持久 | Agent 手动写 |
| L4 | **经验域** (Hindsight) | PG `memory_units` (pgvector) | 长期 | 自动 retain + 聚类增强 |
| L5 | **知识域** (知识树) | PG `knowledge_tree` (pgvector) | 长期 | 离线 builder + 在线 plugin |

```
                    自进化飞轮
    ┌─────────────────────────────────────────────────┐
    │                                                 │
    ▼                                                 │
[用户输入] ──→ [知识导航插件] ──→ [LLM 调用] ────────┘
    │              │
    │     ┌────────┴────────┐
    │     ▼                 ▼
    │  经验域(L4)        知识域(L5)
    │  (Hindsight)       (知识树)
    │     │                 │
    │     ▼                 ▼
    │  聚类脚本         知识树 builder(离线)
    │  因果链           知识树 plugin(在线)
    │  实体挂靠
    │  记忆清理
    │     │
    └─────┘
```

## 二、双域对比

| 维度 | 经验域 (L4) | 知识域 (L5) |
|------|-------------|-------------|
| 数据源 | 对话过程中自动 retain | 精读笔记/审计报告/技术文章 |
| 数据结构 | 平铺语义向量 | 结构化二叉树（领域→科目→知识） |
| 知识分类 | 无分类，语义检索 | 五分类（原理/公式/要点/结论/方法） |
| 检索方式 | 三路 RRF（语义+BM25+实体图+因果链） | 关键词匹配 + cosine 语义 |
| 增强管道 | 聚类分析 + 因果链 + 实体挂靠 | 纠错回路（consolidate） |
| 写入入口 | Hindsight retain API | `knowledge-tree-builder run --merged` |

## 三、知识树管线

### Pipeline

```
扫描 → 阶段1+2(合并模式LLM提取) → 阶段3(准入去重) → 阶段4(树定位写入) → consolidate(周期维护)
```

### 维护命令

```bash
knowledge-tree-builder run --input-dir <目录> --merged -j 3   # 建树
knowledge-tree-builder backfill-k-vectors                       # k_vector回填
knowledge-tree-builder redistribute                            # 领域重分类
knowledge-tree-builder consolidate run                          # 一键维护(cron 周一10:30)
```

### Cron: consolidate 自动执行

| 阶段 | 动作 |
|------|------|
| 1 | 碎片 domain 合并（子节点<5） |
| 2 | 子科目拆分（HDBSCAN，>50触发） |
| 3 | confidence 更新 |
| 4 | 跨科建边（共现率>80%） |
| 5 | 超时审查项处理 |

## 四、知识导航插件管线

```
用户消息 → 熔断器检查 → Hindsight recall(经验域) + 知识树 recall(知识域)
  → 排除标记记忆 → HitCounter → Compaction → 跨域去重(threshold=0.85)
  → 分数过滤(时态衰减可选) → XML <memory-context> 注入 → TaskTracker
  → 注入 user_message
```

关键机制：熔断器（连续3次失败熔断120s）、Compaction（超20轮降为1条）、跨域去重（防止两域结果重复）

## 五、自进化飞轮

```
用户输入 → 知识导航融合双域 → 增强 LLM 上下文 → 更好输出
  → 对话产生新经验(Hindsight retain) + 新知识(知识树 plugin)
  → 知识树周期维护(consolidate cron)
  → 下一轮 recall 更精准 → ↑
```

经验域记"做过什么"，知识域记"是什么"，知识导航决定"什么时候用什么"。两域互补而非替代。
