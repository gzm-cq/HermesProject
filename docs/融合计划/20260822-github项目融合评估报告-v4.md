## 三、专项调研：知识导航 Router

### 3.1 现状问题

知识导航插件的 `pre_llm_call` 当前路由逻辑：
- 按固定顺序查 Hindsight → 知识树 → SAG → codegraph
- 每个源都查，不管 query 是否需要
- 没有 query 分类，没有路由决策，没有验证

### 3.2 查到的相关项目

| 项目 | ⭐ | 核心思路 | 与我们关系 |
|------|----|---------|-----------|
| **RealRoute** (arXiv 2604.20860) | 新论文 | 🏆 **最相关** —— 放弃"先预测路由再检索"的 LLM-as-Router 范式，改为**先并行检索所有源，再统一验证** | 解决我们"路由决策错误"的问题 |
| **vLLM Semantic Router** | 高 | 信号驱动的决策路由，支持多模态 | 太重，vLLM 生态绑定 |
| **aurelio-labs/semantic-router** | 高 | 语义路由，预编码示例→最近邻分类 | 简单，但不够细粒度 |
| **RAGRoute** (sacs-epfl) | 低 | 轻量联邦搜索路由 | 跟我们的多源结构匹配 |
| **Smart Router Kit** | 低 | LLM 路由到工具/数据源 | 太简化 |

### 3.3 核心发现：RealRoute 的 Retrieve-then-Verify 范式

**论文地址**：https://arxiv.org/abs/2604.20860
**代码**：https://github.com/RealRoute（待确认）

**核心思想**：
```
传统路由（LLM-as-Router）：
  query → LLM 预测"该查哪个源" → 只查一个源 → 返回结果
  问题：LLM 预测错误 → 信息来源错 → 回答错

RealRoute（Retrieve-then-Verify）：
  query → 并行查所有源 → 统一证据池 → 动态验证过滤 → 返回结果
  优点：不依赖单次路由预测，证据级验证更可靠
```

**与我们的关系**：我们当前的路由是"先预测再查"（LLM 决定查 Hindsight 还是知识树还是 SAG），RealRoute 的"先并行查再验证"正好解决路由决策错误问题。

**集成方式**：借鉴理念。知识导航插件当前已经并行查 Hindsight + 知识树 + SAG + codegraph，但我们缺少**验证环节**——RealRoute 的 Adaptive Cap 动态证据预算和后续验证链是我们可以直接复制的设计模式。

## 四、专项调研：Skill 召回

### 4.1 现状问题

Hermes 的 skill 加载机制：
- `available_skills` 列表在 system prompt 中，约 110 个
- 靠 skill 名称和描述匹配
- 没有语义检索，没有重排，没有优先级

### 4.2 查到的相关项目

| 项目 | ⭐ | 核心思路 | 与我们关系 |
|------|----|---------|-----------|
| **SkillRouter** (zhengyanzhao1997) | 开源 | 🏆 **最相关** —— 微调 bi-encoder + reranker 做 skill 检索，0.6B 模型已发布 | 直接解决 skill 召回问题 |
| **SkillPilot** (RealTapeL) | 3 | 零配置 skill 指纹识别 + 冲突感知路由 + 自学习反馈 | 理念参考，但太早期 |
| **SkillCorpus** (EverMind-AI) | 新 | SKILL.md 检索基础设施 | 如果我们要建 skill 索引库可以用 |
| **R3-Skill** (Tencent) | 新 | "Skill Is Not Document"——两阶段检索器 | 论文参考，代码刚发布 |
| **self-learning-skill** (philschmid) | 92 | Agent 从网页学习新技术生成 skill | 理念参考 |

### 4.3 核心发现：SkillRouter

**项目地址**：https://github.com/zhengyanzhao1997/SkillRouter
**论文**：arXiv 2603.22455 (Skill Routing for LLM Agents at Scale)

**核心思路**：
```
第一阶段：bi-encoder 检索
  query → SR-Emb-0.6B → 从 77K skill 池中召回 top-50
  
第二阶段：cross-encoder reranker
  top-50 candidates → SR-Rank-0.6B → 重排 → top-1 或 top-10

两阶段总耗时：<50ms（0.6B 模型）
```

**微调数据**：37,979 条 skill 路由 query，hard-negative mining + 三层假阴性过滤

**已发布模型**（HuggingFace）：
- `pipizhao/SkillRouter-Embedding-0.6B` — 第一阶段检索
- `pipizhao/SkillRouter-Reranker-0.6B` — 第二阶段重排

**与我们关系**：直接解决"技能召回"问题。我们的 `available_skills` 列表中有 110 个 skill，当前靠名称匹配，SkillRouter 的两阶段检索可以：
1. 根据 query 语义召回到相关 skill
2. 用 reranker 精确排序
3. 不再需要加载全部 110 个 skill 的描述到 context

**集成方式**：拷贝源码进去。SkillRouter 的推理代码（不含训练）是轻量级的——加载 0.6B 模型做推理，不需要 GPU（6B 模型才需要）。拷贝 `src/` 下的推理代码到 HermesProject 的 `scripts/skill-router/` 目录。
