## 二、第一批（P0）详细 SPEC

### 2.1 SkillRouter — Skill 语义召回

**目标**：把 skill 召回从名称匹配升级为语义检索+reranker

**现状**（codegraph 确认）：
- `_do_skill_match`（router.py:308）→ `skill_matcher.match_skills(query)`
- `match_skills` 是三阶段：keyword → embedding(bge-m3) → LLM
- 问题：embedding 阶段用通用 bge-m3，对 skill 描述的语义匹配不够精确

**改造点**：
- 拷贝 SkillRouter `src/` 下 7 个文件（663 行，MIT）到 `/mnt/d/HermesProject/scripts/skill-router/`
- 下载 HuggingFace 模型：`pipizhao/SkillRouter-Embedding-0.6B` + `pipizhao/SkillRouter-Reranker-0.6B`
- 修改 `skill_matcher.py` 的 embedding 阶段：从 bge-m3 → SkillRouter bi-encoder 召回 top-20 + reranker 重排 top-5
- 不改 `_do_skill_match` 的调用方（router.py 不动）

**文件清单**：
```
新建：scripts/skill-router/
  ├── __init__.py
  ├── run_open_model_eval.py    (227行, 拷贝)
  ├── common.py                  (134行, 拷贝)
  ├── export_retrieval.py        (63行, 拷贝)
  ├── evaluate_predictions.py    (84行, 拷贝)
  ├── metrics.py                 (69行, 拷贝)
  └── data_io.py                 (56行, 拷贝)

修改：plugins/knowledge-navigation/src/knowledge_navigation/core/skill_matcher.py
  └─ embedding 阶段替换为 SkillRouter 推理调用
```

**依赖**：0.6B 模型 ~1.2GB 内存，WSL2 CPU 可运行

**验收**：
1. `match_skills("部署代码")` 返回 `github-workflows` 而非随机匹配
2. top-5 命中率对比当前基线提升 ≥10%
3. 推理延迟 <500ms（0.6B CPU）

### 2.3 Vestige 理念 — 遗忘机制

**目标**：Hindsight 记忆不再只增不减

**现状**：Hindsight 24K+ 条记忆，无遗忘机制，无 access_count 字段

**改造点**（自实现，不安装 AGPL 的 vestige-mcp-server）：
- 知识导航插件维护 `access_count` 和 `last_access_time`（写入 Hindsight memory_links.weight）
- 新建 `memory-weeder` skill，cron 每 7 天跑一次衰减
- `pre_llm_call` 中过滤 `low_priority` 标记的记忆

**文件清单**：
```
新建：skills/memory-weeder/SKILL.md
新建：scripts/memory-weeder/weed.py    (~50行)
  └─ weight = 0.9 ** days_since_last_access
  └─ weight < 0.2 → mark low_priority

修改：plugins/knowledge-navigation/src/knowledge_navigation/core/hooks/router.py
  └─ _dedup_and_measure 之后增加 low_priority 过滤
```

**验收**：
1. 30天未访问的记忆 weight < 0.2，不再注入上下文
2. 被降权的记忆不包含高价值信息（人工抽查 10 条）

### 2.4 codegraph — 接入飞轮

**目标**：代码知识在知识导航中可检索

**现状**（codegraph 确认）：
- codegraph 已安装，CLI 可用（`codegraph query --json`）
- `_execute_recall`（router.py:541）有四路并行召回，无 codegraph 路
- 插件不能调 Tool Registry（MCP 工具），但可以 subprocess 调 CLI

**改造点**：
- 在 `_execute_recall` 的串行分支（router.py:675 的 `else` 块）之后增加条件性 codegraph 调用
- 关键词匹配触发：query 包含"函数"/"调用"/"源码"/"def"/"class" 等代码关键词时触发
- subprocess 调 CLI，不走 MCP/HTTP 桥（无连接泄漏）

**文件清单**：
```
修改：plugins/knowledge-navigation/src/knowledge_navigation/core/hooks/router.py
  └─ _execute_recall 末尾增加 _do_codegraph_recall 条件调用 (~15行)

新建函数：_do_codegraph_recall(query) → list[dict]
  └─ subprocess.run(["codegraph", "query", query, "--json", "--limit", "5", "--path", "/mnt/d/HermesProject"])
```

**验收**：
1. query="pre_llm_call 函数" 返回 router.py 的函数定义和位置
2. 非代码 query 不触发 codegraph（关键词过滤）
3. subprocess timeout=5s，不阻塞主召回流程

## 三、第二批（P1）详细 SPEC

### 3.1 auto-harness — WeaknessMiner 自实现

**目标**：从失败轨迹系统化挖掘模式，接入 skillopt-sleep

**现状**：飞轮 L1 三大算子修正单次错误，skollopt-sleep 的 `mine.py` 已有 `heuristic_mine` 和 `llm_miner`

**改造点**（借鉴 auto-harness 理念，不拷贝源码——原项目耦合 Terminal-Bench）：
- 新建 `WeaknessMiner` 类：从 trace.log 提取失败轨迹，聚类为 weakness pattern
- 新建 `RegressionTester` 类：Docker 沙箱跑回归测试验证 skill 修改
- 接入 `skollopt-sleep/mine.py` 的 `mine()` 函数

**文件清单**：
```
新建：scripts/auto-harness/weakness_miner.py     (~120行)
新建：scripts/auto-harness/regression_tester.py  (~80行)
修改：scripts/skillopt-sleep/skillopt_sleep/mine.py
  └─ mine() 增加 weakness_mine 调用入口
```

**验收**：
1. 从 trace.log 提取出 ≥3 个 failure pattern
2. pattern 接入 llm_miner 产出 TaskRecord
3. RegressionTester 在 Docker 沙箱中跑通

### 3.3 Ouroboros — 审查闭环

**目标**：SE-Agent 算子产出修正后经多 LLM 审查 + Git 追踪

**现状**：Revision 算子产出修正后无审查环节

**改造点**（借鉴 Ouroboros 模式，不部署 runtime）：
- Protected surface：SKILL.md frontmatter 不可被自动修改
- Multi-model review：3 个 LLM 独立审查修改提案 → 投票
- Git 追踪：每次自动修改生成 commit，可 revert

**文件清单**：
```
修改：scripts/self-evolving/src/self_evolving/operators/revision.py
  └─ 产出修正后增加 _multi_model_review() (~100行)
  └─ 增加 _protected_surface_check() (~50行)
修改：scripts/self-evolving/src/self_evolving/operators/refinement.py
  └─ 增加 protected surface 检查
```

**验收**：
1. Revision 产出经 3 LLM 审查，多数通过才 deploy
2. SKILL.md frontmatter 不被自动修改
3. 每次修改有 Git commit，可 revert
