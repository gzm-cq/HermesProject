### P0-2 Cognee（镜像路线废弃，改 pip 安装路线）
- **镜像调查结论（2026-08-23）**：cognee-mcp 官方仅发 Docker 镜像（`ghcr.io/cognee/cognee-mcp`，原报告写的 `topoteretes/cognee-mcp` 仓库名也是错的）。本机对 **ghcr.io / Docker Hub 主站均不可达**（token 都拿不到）；国内镜像源 `docker.1ms.run` / `docker.xuanyuan.run` / `docker.1panel.live` / `docker.m.daocloud.io` / `ccr.ccs.tencentyun.com` / 阿里云 全部实测：**只缓存 Docker Hub 官方库，不缓存 cognee 这个第三方仓库**（UNAUTHORIZED/DENIED）。**任何国内镜像都拉不到此镜像** → 镜像路线在本机整体不可行。
- **新路线（已验证可行）**：cognee-mcp 实为 Python 包（PyPI `cognee-mcp` 0.5.5，入口命令 `cognee-mcp`，依赖 `cognee[postgres-binary,docs,neo4j]`）。PyPI 清华/阿里云镜像在本机 **HTTP 200 可达**，故改用 `pip install cognee-mcp --target=/root/.hermes/cognee-mcp-pkg`（加 `--extra-index-url https://download.pytorch.org/whl/cpu` 拉 CPU 版 torch，该索引本机可达）。
- `scripts/cognee-setup/docker-compose.yml`：**仅保留 neo4j**（Docker 官方镜像 `docker.1ms.run/library/neo4j` 已验证可拉），删去 cognee-mcp 容器。
- `scripts/cognee-setup/start-cognee.sh`：改为 `up`(启 neo4j+校验) / `down` / `check` / `register`(打印 config.yaml 注册段)。
- **注册**：cognee-mcp 由 Hermes 核心以 **stdio** 拉起，注册段（写 `/root/.hermes/config.yaml` 的 `mcp_servers`）见 `start-cognee.sh register`。改配置，不破约束。
- **验证（2026-08-23 已通过）**：
  - 安装：`pip3 install --target=/root/.hermes/cognee-mcp-pkg cognee-mcp` 成功（cognee-mcp 0.5.5 + cognee 1.5.0 + torch CPU），清华/pytorch-cpu 镜像可达。
  - `cognee-mcp --help` 正常，默认 `--transport stdio`。
  - **stdio MCP 握手通过**：`initialize` 返回 `serverInfo: Cognee 1.29.0` + 完整 capabilities。
  - **暴露 11 个工具**，核心 `remember`(写入图谱) / `recall`(跨科语义召回，飞轮目标) / `forget` / `cognify_file` 等。
- **结论**：镜像问题已彻底解决（无需任何镜像），P0-2 从阻塞转为「装好即可启用」，仅剩生产侧注册（改 config.yaml + 重启网关，不破约束）。
