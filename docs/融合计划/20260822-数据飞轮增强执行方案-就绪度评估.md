## 三、跨任务阻塞项（Top 5，决定整体节奏）

1. **Docker daemon 未启动 + Hub 直连超时**
   影响：P0-2 Cognee、P1-2 Graphiti。
   解决：启动 Docker Desktop；在设置中配置镜像加速器（如 `https://registry.cn-hangzhou.aliyuncs.com`），验证 `docker pull` 可用。

2. **HF / GitHub 直连超时**
   影响：P0-1 SkillRouter（模型 + 源码）。
   解决：模型用 `HF_ENDPOINT=https://hf-mirror.com`；源码经 gitclone.com 镜像或手动拷贝（MIT，663 行，体积小）。

3. **Cognee MCP 接入点不明**
   全仓搜不到 `mcp_servers` 配置。知识导航插件如何声明 MCP server、是否由 Hermes 核心统一接管，决定该任务是否越界（受"不改 Hermes 核心"约束）。**须先确认，否则可能做在错误的地方。**

4. **codegraph 索引未建 + 跨环境调用未验证**
   P0-4 的 CLI 在 Windows 侧，Hermes 运行时在 WSL2。subprocess 从 WSL2 调 Windows 的 `codegraph` 并传 `--path /mnt/d/...` 的路径/可执行解析均需实测。先 `codegraph init D:/HermesProject` 建索引。

5. **trace.log 语料过小**
   WeaknessMiner 验收要求"提取 ≥3 个 failure pattern"，但现有 trace.log 仅 20 行且全为超时，无失败轨迹。需改用飞轮运行日志 / SAG 历史 / 评测 trace 作为数据源。

## 五、逐项明细

### P0-3 Vestige 遗忘机制 🟢
- 落点：`memory_links` 加 `access_count`/`last_access_time`（`db.py` 已用 `weight` 字段，扩展安全）。
- 新建 `skills/memory-weeder/` + `scripts/memory-weeder/weed.py`；`router.py` `_dedup_and_measure`(744) 后加 `low_priority` 过滤。
- ⚠️ 冲突风险：已存在 `scripts/memory-cleanup/`（含 `memory-classify-v6.py`、`daily_dryrun.sh`）。建议**复用/扩展**而非新建第二套，避免双写逻辑冲突。

### P0-4 codegraph 接入 🟡
- 落点：`_execute_recall`(541) 末尾加条件性 `_do_codegraph_recall`（~15 行），关键词触发。
- 前置：`codegraph init D:/HermesProject` 建索引（否则 "not initialized"）。
- 风险：CLI 在 Windows、运行时在 WSL2，subprocess 跨环境调用需实测；`--path` 用 `/mnt/d/...` 还是 `D:/...` 需验证。

### P1-3 Ouroboros 审查闭环 🟢
- 落点：`operators/revision.py` 加 `_multi_model_review()` + `_protected_surface_check()`；`refinement.py` 加 protected surface 检查。路径**已验证存在**。
- 纯代码，多模型审查可复用现有 LLM 客户端。

### P1-1 WeaknessMiner 🟡
- 落点：新建 `scripts/auto-harness/weakness_miner.py` + `regression_tester.py`；接 `skillopt-sleep/mine.py`。
- 数据源缺口：现有 `trace.log` 仅 20 行过期超时记录，无法满足"≥3 失败模式"。建议改读飞轮/SAG 运行日志或构建合成 trace。

### P0-1 SkillRouter 🟠
- 落点：`skill_matcher.py` embedding 阶段（现为 API 调用）替换为本地 0.6B bi-encoder + reranker。
- 模型：`HF_ENDPOINT=https://hf-mirror.com` 可下（hf-mirror HTTP 200）。
- 源码：GitHub 直连超时；用 gitclone.com 镜像或手动拷贝 7 文件（MIT）。
- 推理：0.6B CPU ~500ms，WSL2 可行。

### P1-2 Graphiti 🟠
- `pip install graphiti`（pypi HTTP 200 ✅）。
- Neo4j 需 Docker 容器：启动 Docker + 配镜像拉 `neo4j` 镜像。
- 桥接服务 `scripts/graphiti-bridge/bridge.py` 纯代码。

### P0-2 Cognee 🔴
- 硬阻塞在**架构确认**：全仓无 `mcp_servers` 配置，MCP server 声明位置未知，可能属 Hermes 核心（受约束不可改）。
- 即便代码可行，也需先确认"知识导航插件如何接入 MCP"这一接口，否则改动可能无效或越界。
- 镜像层：Docker 启动 + 配镜像可拉 Cognee 镜像。

### P2 MemSkill / EvoAgentX 🟢
- 仅理念借鉴 + 评测，无外部硬依赖，可随时做。

## 六、结论

- **4 项可立即推进**（Vestige、Ouroboros、codegraph[先 init]、WeaknessMiner[先补数据]），均为纯代码改动，是低风险开局。
- **3 项需前置**：SkillRouter（配 HF/GitHub 镜像）、Graphiti（启动 Docker + Neo4j 镜像）、Cognee（启动 Docker + 镜像）依赖网络/服务，但**镜像通路已验证可用**，非死路。
- **1 项待澄清**：Cognee 的 MCP 接入点是唯一架构性未知，建议优先用一次短会/查 Hermes 核心确认，再排期。
- **两个隐性风险**：① Vestige 与现有 memory-cleanup 可能重复建设；② codegraph 跨 Windows/WSL2 调用需在真实运行时验证。
