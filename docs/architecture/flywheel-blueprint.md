## 🥇 P0：反馈飞轮

**闭环逻辑**：
```
用户交互 → 收集反馈（显式 👍/👎 + 隐式跳过/重读/复制/采纳）
       → 反馈聚合 + 归因（哪类 query 失败、为什么）
       → 触发技能/流程优化（SkillOpt 已经在做一部分）
       → 优化后效果被新反馈验证
       → 回到"用户交互"
```

**已有底座**：
- SkillOpt-runner：基于负反馈自动优化技能文档
- self-evolving：自动修改代码

**要补的环节**：
- **显式反馈采集**：每次回复都提供 👍/👎 一键反馈（飞书卡片按钮）
- **隐式信号采集**：记录用户是否复制、重读、追问、跳过
- **归因分析**：把反馈聚类到具体 query 类型 / 具体技能 / 具体来源
- **闭环验证**：优化后同一类 query 反馈是否改善

**为什么优先**：成本最低（埋点 + 飞书按钮），价值最高（驱动所有其他飞轮）

---

## 🥇 P0：经济飞轮

**闭环逻辑**：
```
任务执行 → 记录 token 消耗 + 任务耗时 + 价值产出
       → 成本-价值模型（哪些任务 ROI 高、哪些低）
       → 路由策略优化（高价值任务用大模型、低价值用小模型）
       → 跳过冗余步骤
       → 节省的 token 投到高价值任务
       → 单位价值成本下降 → 更多任务能被承担
       → 回到"任务执行"
```

**已有底座**：
- LiteLLM 网关（已经能看到调用量）

**要补的环节**：
- **成本埋点**：每个任务记录 token in/out、模型、耗时、缓存命中
- **价值归因**：把产出质量（如 Hindsight 召回率、对话满意度）反向归因到任务
- **路由优化规则**：高复杂度任务 → 大模型；简单任务 → 小模型 / 缓存
- **预算熔断**：单任务/单日 token 超限自动降级或告警

**为什么优先**：直接省钱、有量化 ROI、可立刻在 LiteLLM 层做

## 🥈 P1：元认知飞轮

**闭环逻辑**：
```
模型回答 → 识别"我不知道"的时刻 + 错误推理 + 边界模糊
        → 提炼知识盲区 / 推理漏洞 / 任务边界
        → 沉淀到"边界知识库"（带可信度标签）
        → query 改写 / 拒答 / 转人工 / 标注不确定
        → 盲区覆盖率被新数据验证
        → 回到"模型回答"
```

**已有底座**：
- Hindsight（可以记录低质量回答）

**要补的环节**：
- **不确定性检测**：监控回答中的"应该/可能/大概"等模糊词频率
- **拒答/转人工策略**：低置信度场景自动转 myHermes
- **边界知识库**：哪些领域、哪些类型 query 已知答不好
- **改进跟踪**：同一类 query 的低质率随时间变化

**价值**：建立"知道自己不知道"的能力，长期减少用户失望

---

## 🥈 P1：协作飞轮

**闭环逻辑**：
```
多 agent 协作任务 → 记录协作轨迹（谁负责什么、何时交接、结果如何）
              → 提炼协作模式（谁擅长什么、什么场景配合最优）
              → 沉淀"智能体能力图谱"（per-agent 能力/擅长领域/历史表现）
              → 任务路由自动选最佳 agent
              → 协作效率被新任务验证
              → 回到"多 agent 协作任务"
```

**已有底座**：
- 群聊里 myHermes + 高民的智能伙伴 已经在协作

**要补的环节**：
- **能力图谱**：每个 agent 的能力标签 + 擅长领域 + 历史准确率
- **任务路由**：根据 query 类型 + 能力图谱 + 上下文自动选 agent
- **协作模板**：常见多 agent 协作模式（review + 部署、调研 + 写作等）固化

**价值**：高民在群里已经手动 @ 多个 bot，自动化这部分省时

## 🥈 P1：知识飞轮

**闭环逻辑**：
```
对话/任务 → 提取事实/结论/决策
        → 聚类 + 关联 + 抽象
        → 沉淀到知识树 + Hindsight（已有 pipeline）
        → RAG 召回复用
        → 复用率被新召回数据验证
        → 优化提取/聚类/检索
        → 回到"对话/任务"
```

**已有底座**：
- knowledge-tree-builder（文档→知识点提取→聚类→分层→PG）
- Hindsight（三路召回 + RRF）
- knowledge-navigation（双路径融合）

**要补的环节**：
- **复用率指标**：知识节点被召回后被采纳的比例
- **冷热分层**：热知识（高频召回）放快路径、冷知识放慢路径
- **去重与冲突消解**：同源 vs 异源、版本演化

**价值**：知识资产越来越值钱，但需要"用起来"才有飞轮

## 🥉 P2：工具飞轮

**闭环逻辑**：
```
工具调用 → 记录调用成功率/失败模式/误用/超时
        → 提炼工具短板 + 误用模式
        → 沉淀"工具使用规范" + 替代工具候选
        → 智能体自动选工具 + 错峰调用
        → 调用效率被新场景验证
        → 回到"工具调用"
```

**实施成本**：需要全量工具调用埋点 + 工具库画像

## 🥉 P2：信任飞轮

**闭环逻辑**：
```
用户交互 → 信任信号（采纳/拒绝/修改/质疑）
        → 提炼哪些场景信任度高/低
        → 沉淀"可信度评估模型"
        → 高风险场景自动转人工 + 显示来源
        → 信任度被新交互验证
        → 回到"用户交互"
```

**实施成本**：需要可解释性 + 来源溯源 + 信任评分

---

## 🥉 P2：演化飞轮（自进化的元飞轮）

**闭环逻辑**：
```
self-evolving 算子输出 → 记录哪些修改被采纳 / 被回滚
                  → 提炼演进策略（什么类型修改更可能成功）
                  → 沉淀"演进策略库"
                  → 自动演进 vs 人工 review 决策
                  → 演进成功率被新周期验证
                  → 回到"self-evolving 算子输出"
```

**实施成本**：依赖 self-evolving 已有足够的运行数据

## 飞轮间的关系

```
                    ┌─ 数据飞轮 ─┐
                    │           │
                    │   能力飞轮 ◄───── 反馈飞轮（驱动所有）
                    │           │
                    └─ 知识飞轮 ┘
                           ▲
                           │
   协作飞轮 ──► 元认知飞轮 ─┘
        │              ▲
        │              │
        └──► 工具飞轮 ─┘

                  经济飞轮（约束所有）
                  信任飞轮（护城河）
                  演化飞轮（元飞轮）
```

- **反馈飞轮** = 元飞轮，驱动其他所有飞轮
- **经济飞轮** = 约束飞轮，限制所有其他飞轮的成本
- **信任飞轮** = 护城河，决定飞轮的可持续性
- **演化飞轮** = 元飞轮，管 self-evolving 本身的质量

## 实施建议

**第一波（建议立刻做）**：
1. **反馈飞轮**：飞书卡片加 👍/👎 + 隐式信号埋点
2. **经济飞轮**：LiteLLM 加 token 成本埋点 + 路由优化

**第二波（数据积累后做）**：
3. **元认知飞轮**：基于反馈数据识别盲区
4. **知识飞轮**：复用率指标驱动知识树优化

**第三波（生态成熟后做）**：
5. 协作飞轮、工具飞轮、信任飞轮、演化飞轮

> 关键原则：**先闭环一个，再扩到下一个**。一次做 8 个飞轮 = 一个都做不起来。

## 与你已有飞轮的连接点

| 已有飞轮 | 与新飞轮的连接 |
|----------|----------------|
| **数据飞轮** | + 反馈飞轮 = 数据有"质量信号"；+ 经济飞轮 = 数据有"成本信号" |
| **能力飞轮** | + 协作飞轮 = 能力有"被用场景"；+ 元认知飞轮 = 能力有"边界" |
| **self-evolving** | + 演化飞轮 = 自动修改有"质量监控"；+ 信任飞轮 = 自动修改有"可解释性" |

每加一个新飞轮，都是在给已有飞轮**补信号**或**加约束**。
