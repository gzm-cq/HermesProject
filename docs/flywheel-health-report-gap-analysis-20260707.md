# 飞轮健康检查报告 — 缺口分析

**日期**: 2026-07-07
**背景**: P1 问题全清后评估，当前报告覆盖 4 类（任务可靠性、产出质量、变化趋势、数据可信度），以下为逐飞轮识别的缺失项。

---

## 1. Router 飞轮 — 缺延迟分位

**现状**: 只报平均延迟和最大延迟。
**数据**: p50=2660ms, p95=4930ms, p99=14790ms（p99 比 p50 高 5.5 倍）。
**建议**: 加 p95/p99 延迟分位数，平均值掩盖尾部超时。

## 2. Hindsight 飞轮 — 完全缺失

**现状**: 报告里没有 Hindsight 的健康指标。
**数据**: 59654 memory_units, 15635 entities, 154万 memory_links, daemon 0 重启无错误。
**建议**: 加 daemon 状态（active/restart 次数）、memory_units 总量及增量、熔断器状态。

## 3. Skill 飞轮 — 缺零分查询分析

**现状**: F1=0.5189，只报平均分不报分布。
**数据**: 30 个查询中 5 个 F1=0（完全没匹配），零分率 16.7%。
**建议**: 加零分查询数和占比，比平均分更能暴露问题。

## 4. 记忆飞轮 — 缺 MEMORY.md 容量预警

**现状**: 不监控 MEMORY.md/USER.md 容量。
**数据**: MEMORY.md 已到 82%（40766/50000），USER.md 到 80%（11998/15000）。
**建议**: 加容量占比，>80% 标 P1 预警。

## 5. 知识路 — 缺入库产出量

**现状**: daily-learn 只报状态 success，不报当天入了多少条知识入树。
**建议**: 从日志中提取当日入库 KP 数。

## 6. 基础设施 — 缺 LiteLLM 和 Gateway 状态

**现状**: 不检查 LLM 网关健康。
**数据**: LiteLLM healthy_endpoints=0（可能是空响应），Gateway NRestarts=0。
**建议**: 加 LiteLLM 健康检查、Gateway 重启次数和 uptime。

---
